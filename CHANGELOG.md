## 0.3.4 — 2026-11-09: the lab image is rebuilt so Debian's fixed zlib is included

This release exists so the published lab image can be rebuilt with Debian's fixed `zlib`. On 2026-11-09 the website's Docker Scout check found two fixable HIGH findings in the published `img-mo-lab-addon:v0.3.3` image, both in Debian 13's `zlib1g` (the compression library almost every program in the image links to): [CVE-2026-76844](https://security-tracker.debian.org/tracker/CVE-2026-76844) and [CVE-2026-85091](https://security-tracker.debian.org/tracker/CVE-2026-85091), two heap buffer overflows in zlib's `gz*` write functions (website issue [HCW-HybridCloudWorks#1600](https://github.com/saulpatinojr/HCW-HybridCloudWorks/issues/1600)). - `core-update.yml` now runs from `main` only, and auto-merge no longer listens to the `bump` job's report. Two High findings from the review of the two-job split (pull request 57, which merged before they were fixed). First, a person with write access could start the workflow by hand on another branch (a manual run of `core-update.yml` with `--ref` set to any branch other than `main`); the `pull-request` job would then run that branch's `scripts/core-update-pin.mjs` before minting the App token, and a changed script could skip the checks.
